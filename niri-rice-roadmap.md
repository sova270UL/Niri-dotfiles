# Роадмап: niri-рис на Quickshell + wallust

Обновлено: 2026-10-31

## TL;DR

Цель: собрать отдельную от Hyprland сессию niri, где одна команда меняет обои, а палитра на их основе перекрашивает рамки окон, уведомления, бар и меню на Quickshell, терминал и выбранные приложения. Все дотфайлы лежат в одном Stow-пакете `niri` в репозитории `~/dotfiles`.

## Соглашения по коду Quickshell

Правила, по которым собран бар и которым стоит следовать в новых модулях и окнах:

- **Модуль это файл в `components/`, в корне которого `Capsule`.** `Bar.qml` только расставляет модули по `Row` слева, по центру и справа и ничего не знает об их содержимом.
- **`Capsule`** даёт форму (радиус от высоты), подсветку при наведении (`clickable: true` у кликабельных), сигналы `clicked` и `scrolled`, свойство `hovered`. Всё общее поведение капсул правится только там.
- **Числа оформления** (шрифт, размеры, радиусы, отступы, прозрачности, длительность анимации) берутся из singleton `theme/Theme.qml`, а цвета из `theme/Colors.qml` (его значения генерирует wallust в `colors.json`). Забитых чисел в модулях быть не должно.
- **Текст** в модулях это `BarText` (шрифт и цвет из темы, цвет можно переопределить).
- **Данные и логика** лежат в `services/` как singleton (`NiriState`, `Audio`, `Net`), виджеты только читают их свойства.
- **Иконки** это символы Nerd Font, записанные кодами `󰈀`, а не вставленные в файл.
- **Запуск программ** из QML через `Quickshell.execDetached([...])`: процесс не умирает при перезагрузке конфига.
- **Окна меню и панелей** должны быть ленивыми (`Loader` в окне бара, см. 4.6).
- Quickshell перезагружает конфиг сам при изменении файлов. Исключение: смена режима процесса (`pragma`) требует `pkill -x qs` и нового запуска.

## Структура репозитория

```
/home/sova/dotfiles/
└── niri/                         # единственный Stow-пакет
    ├── .config/
    │   ├── niri/                 # config.kdl, input/monitor/layout/startup/windowrule/keybinds, var.kdl, niri-colors.kdl (генерируется)
    │   ├── wallust/              # wallust.toml и templates/
    │   ├── quickshell/niri/
    │   │   ├── shell.qml         # точка входа
    │   │   ├── cava.conf         # конфиг cava (количество столбцов и частота кадров)
    │   │   ├── theme/            # Colors.qml, colors.json (генерируется), Theme.qml (токены)
    │   │   ├── services/         # NiriState.qml, Audio.qml, Net.qml, Launcher.qml, Panels.qml, Osd.qml, Media.qml, Cava.qml
    │   │   └── components/       # Bar, Capsule, BarText, Clock, Workspaces, Tray, Volume, NetworkStatus, KeyboardLayout, LauncherContent, PowerButton, PowerMenuContent, VolumeOsd, VolumeOsdContent, MediaButton, MediaContent, VisualizerWindow, VisualizerBottom, CalendarContent
    │   └── mako/                 # config (генерируется)
    └── .local/bin/               # set-wall.fish и другие скрипты
```

Файлы, которые перезаписывает wallust, лежат в репозитории и коммитятся: `niri-colors.kdl`, `mako/config`, `quickshell/niri/theme/colors.json`.

Проверка структуры и симлинков в любой момент:

```fish
cd ~/dotfiles
stow -n -v niri
ls -l ~/.config | grep -E 'niri|wallust|quickshell|mako'
niri validate
```

Первая команда показывает, что сделает Stow (ничего не меняя), вторая показывает симлинки в `~/.config`, третья проверяет весь конфиг niri вместе с `include`.

## Частые проблемы

| Проблема | Причина | Решение |
|---|---|---|
| `niri validate` ругается на `include "niri-colors.kdl"` | Файл не существует, wallust ещё не запускался | `touch ~/dotfiles/niri/.config/niri/niri-colors.kdl`, затем один запуск `set-wall.fish` |
| Новые окна терминала с цветами по умолчанию | Wallust красит только уже открытые терминалы | Блок с выводом `~/.cache/wallust/sequences` в `config.fish` (сделано, пункт 1.4) |
| Окна потеряли прозрачность | Правило `place-within-backdrop` для `awww-daemon` | Удалить правило (сделано, пункт 1.5) |
| Обои пустые после входа в сессию | `awww-daemon` стартует без картинки | Восстановление обоев при входе (пункт 1.6) |
| `command not found` для скрипта | `~/.local/bin` не в `PATH` | `fish_add_path ~/.local/bin` или полный путь |
| `stow` не создаёт симлинк | В `~/.config/<программа>` уже лежит реальная папка | Сделать бэкап, перенести файлы в пакет, затем `stow` |
| `color is not a type` в `Colors.qml` | Нет `import QtQuick`, тип `color` приходит оттуда | Добавить `import QtQuick` в начало файла (сделано, пункт 2.2) |
| Иконки в баре рисуются квадратами | В системе нет Nerd Font | Установить пакет с Nerd Font (например, символьный), проверить `fc-list \| grep -i nerd`, при необходимости указать имя шрифта в `Theme.qml` |
| Меню трея не открывается, в логе `Cannot call QsMenuAnchor.open() as quickshell was not started in QApplication mode` | Платформенные меню требуют режима `QApplication` | Первой строкой `shell.qml` добавить `//@ pragma UseQApplication` и перезапустить Quickshell целиком (`pkill -x qs`), горячая перезагрузка режим не переключает (сделано, пункт 2.4) |
| На экране два бара | Бар запущен и автозапуском, и вручную из терминала | `pkill -x qs`, затем один запуск |
| Бар не загружается, `Type Launcher unavailable` | Файл с тем же именем в `components/` затеняет одноимённый singleton из `services/` | Удалить лишний файл из `components/` |
| Капсулы бара пропали, `nan` и `undefined` в логе | В `Theme.qml` нет токена, на который ссылаются модули | Добавить недостающий токен в `Theme.qml` |
| Сетка лаунчера не помещается в карточку | Высота карточки и сетки считаются из разных значений | Размеры берутся из `Theme` (`launcherHeight` выводится из `gridCellHeight × gridRows`), править только токены |

## Журнал решений

- Один Stow-пакет `niri` вместо пакета на каждую программу: в репозитории только то, что относится к niri.
- Сгенерированные wallust файлы коммитятся в репозиторий.
- Обои в overview не используются, в overview заливка цветом.
- Статичные обои через awww, видео возможно позже.
- Системный монитор, экран блокировки и простой в план не включены.
- Свой сервер уведомлений в Quickshell не делаем, уведомления остаются за mako.
- Минимальный бар поставлен перед оформлением mako: бар задаёт токены стиля, остальное подгоняется под него.
- Конфиг Quickshell называется `niri` (`qs -c niri`), в роадмапе вместо прежнего `lab`.
- Бар: по одному `PanelWindow` на экран через `Variants`, цвета через singleton `Colors` (`FileView` + `JsonAdapter`), время через `SystemClock`.
- Активное окно в баре не показываем: пользователь им не пользуется.
- Дизайн бара: полупрозрачная подложка, каждый модуль в капсуле. Правило: модуль это файл, в корне которого `Capsule`, а `Bar` только расставляет модули по `Row` слева, по центру и справа. Наведение и анимации реализуются один раз в `Capsule`.
- Громкость через нативный PipeWire, а не опрос `wpctl`: события приходят сами. Клик открывает `pavucontrol`, mute из бара убран.
- Сеть через `Quickshell.Networking` (NetworkManager по D-Bus), а не опрос `nmcli`. Имя сети не показывается.
- Иконки только из Nerd Font, коды в QML записаны через `\u`-последовательности, чтобы символы не терялись при копировании.
- **fuzzel убран из стека.** Лаунчер приложений и меню выключения делаются на Quickshell: так возможен единый визуал с баром и анимации, а fuzzel не умеет ни форм, ни капсул, ни анимаций. Цена: больше кода и память `qs`, поэтому панели ленивые (`Loader` в окне бара) и память проверяется замером. Вызов из niri через IPC (`qs ipc call`), `GlobalShortcut` не подходит для niri.
- Менеджер обоев и выбор из истории буфера обмена: решение не принято. `cliphist` как хранилище остаётся в любом варианте.
- Трей через `Quickshell.Services.SystemTray` и `QsMenuAnchor`. Это потребовало режима `QApplication` для всего процесса (`//@ pragma UseQApplication`): принято, цену по памяти замерить (пункт 7.7). Если окажется заметной, меню трея переписывается на `QsMenuOpener` без этого режима.
- Резерв места под бар не настраивается вручную: режим по умолчанию при трёх якорях резервирует высоту окна с отступами.
- Индикатор «не беспокоить» (2.5) признан спорной функцией и отложен в самый конец, возможно не будет делаться.
- Токены оформления лежат в отдельном `theme/Theme.qml` (ручные значения), а не в `Colors.qml` (данные, которые генерирует wallust). Значения в шаблонах mako повторяются вручную; единый источник для QML и mako возможен позже, но сейчас был бы преждевременным усложнением.
- Повторяющийся текст модулей вынесен в `BarText`, чтобы шрифт и цвет менялись в одном месте.
- Лаунчер на `DesktopEntries` без ручного парсинга `.desktop`; вызов через `qs ipc call`, `GlobalShortcut` не используется.
- Лаунчер живёт внутри окна бара ради единого контура; фон при открытии плавно темнеет с `barOpacity` до `launcherOpacity` для читаемости; `exclusiveZone` бара задан явно, чтобы окна niri не двигались.
- Отступ уведомлений сверху равен `gaps` минус ширина focus-ring (2 px), чтобы внешний контур совпадал с кольцом окна.
- Работа ведётся так: проектирует чат-ассистент, агент исполняет, лишнего в git нет.
- Лаунчер перешёл с списка на сетку 5×4: размеры сетки считаются из `Theme` (`gridCellHeight × gridRows`), `launcherHeight` выводится из них, поэтому карточка всегда вмещает сетку.
- Лаунчер открывается только на мониторе с фокусом (`NiriState.focusedOutput`).
- Состояние панелей (лаунчер и меню питания) хранит один `services/Panels.qml` (`current` + `last`): два независимых синглтона пришлось заменить, чтобы содержимое и высота карточки не прыгали при закрытии и не появлялись циклические ссылки. `OverlayPanel` удалён как мёртвый код — история остаётся в git.
- Меню выключения: узкая вертикальная панель из иконок под кнопкой питания; правый край панели заподлицо с баром, потому что вогнутое сопряжение справа не помещается рядом со скруглённым углом бара. Контур строится той же функцией `buildOutline`, для панели ширина постоянна, а высота анимируется.
- Ревью 2026-10-24: числа рабочих пространств вынесены в `Theme`, лишние файлы (`quickshell/lab`, пустой `var.kdl`) удалены, `NiriState` защищён от битых строк `event-stream`.
- Wi-Fi: в Quickshell нет агента паролей NetworkManager, поэтому панель подключает только сохранённые сети, а для новых открывает `nmtui`. Поиск сетей (`scannerEnabled`) включается при открытии панели и сам выключается через 10 секунд, чтобы не гонять радио и не давать всплесков пинга; повторный скан по повторному открытию. Список пересобирается по сигналу модели и раз в 4 секунды, но новый список присваивается модели только при изменении «подписи» (имена, порядок, подключённая сеть), поэтому прокрутка и выбор не сбрасываются; выбор хранится по имени сети. Сортировка по четырём ступеням сигнала и имени, чтобы строки не прыгали; сети слабее 0.1 скрыты, кроме подключённой
- OSD громкости запускается файлом-триггером из биндов niri, а не событием PipeWire и не вызовом `qs ipc call`: GUI-изменения громкости не должны давать попап, на 100% попап нужен, а вызов `qs ipc call` стоит около 0,2 с и около 80 мс процессорного времени на каждое нажатие (при удержании клавиши это десятки вызовов в секунду). Бинд пишет `printf $$` встроенной командой `sh`, без нового процесса.
- В IPC niri нет флага fullscreen, поэтому полноэкранное окно определяется по размеру плитки (`layout.tile_size` не меньше логического размера выхода, допуск 2 px). В полноэкранном режиме бар не показывается, вместо него мини-окно: иначе бар всплывал бы поверх игры. OSD не забирает фокус и пропускает клики (`mask`).
- Первые 1,5 с после старта триггеры игнорируются. Процесс звука повторно не запускается, пока предыдущий не завершён (защита при удержании клавиши).
- Карточка медиа сделана панелью из бара по центру (как лаунчер), а капсула стоит слева от часов, потому что правая часть бара перегружена. Это не отдельное окно: единый контур и один набор анимаций. Капсула в баре скрыта без плеера. Положение трека опрашивается таймером только при открытой панели и воспроизведении, потому что MPRIS не присылает событий положения.
- fuzzel удалён после появления лаунчера. Пакет fuzzel с системы не удаляется автоматически: он может использоваться сессией Hyprland.
- Визуализатор вынесен из бара на слой `Bottom`: он должен быть частью рабочего стола, а не занимать место в баре. Слой `Background` не используется: порядок относительно `awww-daemon` на одном слое не определён. Показ только на пустом рабочем столе и только при воспроизведении: иначе процесс cava потреблял бы процессор впустую. Окно без резерва места и с пустой маской ввода.
- Форма визуализатора это пресет: `VisualizerWindow` выбирает компонент по `Cava.preset`, пресет это `Item` со свойством `values`. Новый вид добавляется файлом и одной записью в `presets`; переключается на лету через IPC. Число столбцов и частота кадров заданы только в `cava.conf`.
- Календарь использует локаль процесса для названий месяцев, дней недели и первого дня недели.
