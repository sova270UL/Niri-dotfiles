# Меню трея в стиле капсул — план релизации

Статус: **выполнен и принят пользователем 2026-11-01** (пункт роадмапа «Собственное меню трея через `QsMenuOpener` в стиле капсул», этап 4 — закрыт).

## Что сделано и проверено на стенде (2026-10-31)

- `services/Config.qml`: тумблер `trayMenuCustom: true` — свои меню; `false` — системное `QsMenuAnchor` как раньше (проверено: при `false` правый клик открывает системное меню того же приложения).
- `services/TrayMenu.qml` (`pragma Singleton`): `QsMenuOpener`, построение строк (`buildRows`: разделитель «линия в строке после разделителя» — чтобы не было binding loop), `show`/`close`/`activate`/`submenu`, `Panels.close()` при открытии.
- `components/TrayMenuContent.qml`: строки (текст через `BarText`), hover-подсветка капсулой, чекбоксы `[x]`/`[ ]`, стрелка `>` у подменю, Esc → `TrayMenu.close()`.
- `components/Tray.qml`: ПКМ → `TrayMenu.show(item, icon, menuWindow)` при `Config.trayMenuCustom`, иначе `menu.open()`; `PopupWindow` (`grabFocus: true`) с карточкой, якорь `anchor.window` через `TrayMenu.anchorItem.QsWindow.window`, `rect` из `itemRect()` в `Connections onAnchoring`.
- Токен `Theme.trayMenuMaxHeight: 480`.
- Замер: левый край карточки 1718 = левый край иконки 1719, верх под иконкой.

Проверено сквозным тестом (инъекция ввода + скриншоты): открытие ПКМ у иконки, положение под иконкой и поверх окон, hover строки, клик по пункту (activate + закрытие), закрытие по клику вне (`grabFocus`), обе ветки `trayMenuCustom`, лог без WARN/ERROR/undefined/nan.

Стендом не покрывались (проверять при появлении проблем): Esc, подменю (`entry.display(...)` — в меню Steam/spotify подменю нет), чекбоксы, второй монитор, взаимоисключение с лаунчером/панелями.

Отклонение от плана: `QsMenuAnchor` в `Tray.qml` **не удалён** — он обслуживает ветку `Config.trayMenuCustom: false` (отключение своих меню: выставить `false` и перезапустить `qs`).

Примечание для отладки: `console.log` из QML попадает в `/run/user/1000/quickshell/by-id/<id>/log.qslog` (бинарный, искать `grep -a`), а не в `~/qs.log`.

## Контекст (проверено на установленном Quickshell 0.3.2)

- `components/Tray.qml`: каждая иконка открывает `QsMenuAnchor { menu: icon.modelData.menu; anchor.item: icon }`, левый клик `activate()`, средний `secondaryActivate()`, правый `menu.open()`, колесо `scroll()`.
- По `quickshell-core.qmltypes` у `QsMenuAnchor` только `menu`, `anchor`, `visible`, `open()`, `close()` и сигналы `opened`/`closed` — **контента и стиля окна API не отдаёт**, оформить существующее меню средствами конфига нельзя (в роадмапе уже зафиксировано: «меню не подчиняется палитре»).
- `QsMenuOpener` (`import Quickshell`): `menu` + `children` (`ObjectModel<QsMenuEntry>`, есть `childrenChanged`) — модель для собственного рендера.
- `QsMenuEntry`: `text`, `icon`, `enabled`, `isSeparator`, `buttonType` (`None`/`CheckBox`/`RadioButton`), `checkState`, `hasChildren`, сигнал `triggered()`, `display(parentWindow, x, y)`.
- Окна: `PopupWindow` (`parentWindow`, `anchor.item`/`edges`/`gravity` через `PopupAnchor`, `grabFocus`, сигнал `closed`, `reposition()`) и `PanelWindow` — доступны уже с `import Quickshell` (модуль `Quickshell._Window` подключён по умолчанию в `qmldir`).
- Бонус: собственное меню не требует режима `QApplication` — если после перехода цена `//@ pragma UseQApplication` (п. 7.7) заметна по памяти, режим можно снимать (решение отдельное, непроверено).

## Этап 0. Ворота: нужно ли своё меню

## Этап 1. Каркас: функциональное меню без оформления

Непроверенный участок — собственное окно, поэтому сначала минимальный стенд.

1. **Стенд (непроверено, проверить в первую очередь):**
   - открытие `PopupWindow` с `parentWindow` окна бара и `anchor.item` = иконка, те же `edges`/`gravity`, что сейчас (`Bottom | Left`, `Bottom | Right`); ссылку на окно бара взять через `Window.window` из `Tray.qml`;
   - закрытие по клику вне меню и по Esc (`grabFocus` + сигнал `closed` — наличие свойств подтверждено, поведение — нет);
   - если клик вне не закрывает — запасной путь: отслеживать фокус (`focusable` у окна) и закрывать при потере.
2. **Файлы:**
   - `services/TrayMenu.qml` (`pragma Singleton` + `Singleton {}`): какой иконке открыто меню, экземпляр `QsMenuOpener`, функции `open(item)` / `close()`; взаимоисключение с панелями: открытие меню вызывает `Panels.close()`, открытие любой панели (`Panels.toggle`) закрывает меню;
   - `components/TrayMenuContent.qml`: `Repeater` по `opener.children` — строка (текст через `BarText`, иконка с `sourceSize` и `asynchronous: true`), разделитель (`isSeparator`), чекбокс (`checkState`/`buttonType`), disabled-состояние (`enabled`), hover, активация `entry.triggered()` с закрытием меню;
   - правки только в `components/Tray.qml`: ПКМ вызывает `TrayMenu.open(...)` вместо `menu.open()`. `QsMenuAnchor` удаляется в этом же шаге (не оставлять два механизма).
3. **Критерий этапа:** левый/средний клик и колесо работают как раньше, все пункты меню кликабельны, меню закрывается после срабатывания пункта, по клику вне и по Esc, при открытом лаунчере/панели они закрываются; в логе нет `ERROR`/`undefined`/`nan`/`Unable to assign`.

## Этап 2. Подменю (ворота)

У пунктов с `hasChildren` два пути:

- **(а)** вложенный `QsMenuOpener` + своё окно по наведению — всё оформлено в капсулах;
- **(б)** `entry.display(parentWindow, x, y)` — подменю рисует платформа, своё оформление только у корневого меню.

Решение принимается по факту: что показывают Steam и Telegram. Путь (б) допустим как первый релиз, (а) — как улучшение.

## Этап 3. Оформление в стиле капсул

- Все числа — из `theme/Theme.qml` (добавить токены под меню: ширина по содержимому, высота строки, внутренние отступы — названия уточняются при реализации), все цвета — из `theme/Colors.qml` (фон карточки, рамка `borderWidth`, hover через токены прозрачности).
- Геометрия по образцу `Capsule.qml`: `radius: height / 2` для строк выделения, карточка меню — радиус как у панелей (`Theme`), `Behavior`-анимация цвета на `Theme.animationMs`.
- Разделитель — тонкая линия на цвете из `Colors`, не хардкод.
- Клавиатурная навигация (Up/Down/Enter/Esc) — отдельное решение пользователя, не обязательный пункт первого релиза.

## Этап 4. Проверка и релиз

```fish
pkill -x qs
qs -c niri 2>&1 | tee ~/qs.log
grep -E "ERROR|undefined|nan|Unable to assign" ~/qs.log
```

Ручной сценарий:

1. ПКМ на иконке Steam и Telegram → своё меню, пункты кликаются, иконки и текст на месте.
2. Открыть лаунчер, затем ПКМ на трее → лаунчер закрыт, меню открыто; наоборот — панель открыта, меню закрыто.
3. Клик вне меню, Esc, выбор пункта → закрывается.
4. Левый клик, средний клик, колесо по иконке → работают как до изменений.
5. `niri validate` не требуется: `.kdl` не меняются.

После релиза решить по п. 7.7: оставить `//@ pragma UseQApplication` в `shell.qml` или снять (непроверено, проверять отдельно).

## Риски

| Риск | Что делать |
| --- | --- |
| Клик вне окна не закрывает меню (поведение `PopupWindow` непроверено) | Запасной путь из этапа 1 — закрытие по потере фокуса |
| Меню — отдельное окно, а не панель бара: поведение на втором мониторе и в раскладке niri | Проверять на обоих мониторах, панели бара живут только на фокусном (`NiriState.focusedOutput`) |
| Динамические пункты (Telegram) | Модель `children` уведомляется (`childrenChanged`), `Repeater` перестроится; проверять на живом приложении |
| Окно меню в niri получает своё место в дереве окон | layer-shell popup, должен быть поверх бара; проверить порядок слоёв глазами |
